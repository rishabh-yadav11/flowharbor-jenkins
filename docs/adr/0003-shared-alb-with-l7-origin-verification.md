# ADR 0003 — One shared ALB with L7 origin verification, not CloudFront-only ingress

- **Status:** Accepted
- **Context:** The stack has four HTTP surfaces (Jenkins, dev, staging, prod). CloudFront in front of all of them would make the origin unreachable directly and hide the Jenkins controller behind a cache, but a per-environment ALB would multiply fixed hourly cost and certificates for a demo.
- **Decision:** A single internet-facing ALB terminates TLS with one wildcard ACM certificate and routes by `Host` header — Jenkins at priority 10, then dev, staging, prod (`terraform/modules/alb/main.tf:151`, `terraform/modules/alb/main.tf:194`, `terraform/modules/alb/main.tf:211`, `terraform/modules/alb/main.tf:228`, `terraform/modules/alb/main.tf:251`); the HTTPS listener's default action is a fixed `404` so an unmatched Host cannot reach any target group (`terraform/modules/alb/main.tf:158`, `terraform/modules/alb/main.tf:163`). When CloudFront is enabled for the production domain, the prod rule also requires a secret `http_header` condition that CloudFront injects on every origin request (`terraform/modules/alb/main.tf:266`, `terraform/modules/alb/main.tf:271`, `terraform/modules/cloudfront/main.tf:140`), so a request for the production hostname that bypasses CloudFront falls through to the 404 default.
- **Consequences:** One certificate, one WAF association, and one place to reason about TLS replaces four stacks; the cost is that the origin stays directly addressable, so the origin-verify header is a bypass guard only when `enable_cloudfront = true` — with CloudFront disabled (the default, `terraform/variables.tf:60`) the production hostname is served straight from the ALB and the guard is simply absent.
- **Rejected alternative:** CloudFront-only ingress for every environment — rejected because CloudFront is optional in this stack, and an origin that is only reachable through a CDN cannot be tested or reached from inside the VPC during a pipeline run.
