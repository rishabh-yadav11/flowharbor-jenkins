# ADR 0006 — GitHub Actions gates PRs, Jenkins performs tag-driven delivery

- **Status:** Accepted
- **Context:** Pull-request checks and production delivery have opposite requirements: PR checks must be fast, free, and visible next to the diff, while delivery needs AWS credentials, a long-lived agent, a manual approval gate, and rollback logic that only makes sense on a controller.
- **Decision:** Both exist and neither duplicates the other. GitHub Actions runs `verify` on pushes and pull requests to `main` across Node 22 and 24 — lint, typecheck, coverage — with `npm ci --ignore-scripts` so no dependency install script executes (`.github/workflows/ci.yml:3`, `.github/workflows/ci.yml:23`, `.github/workflows/ci.yml:37`, `.github/workflows/ci.yml:49`), and a second workflow gates infrastructure changes with `terraform fmt -check -recursive`, `init -backend=false`, `validate`, and a Trivy misconfiguration scan at `HIGH,CRITICAL` with `exit-code: "1"` (`.github/workflows/terraform.yml:44`, `.github/workflows/terraform.yml:48`, `.github/workflows/terraform.yml:52`, `.github/workflows/terraform.yml:67`). Jenkins runs the same quality gate again inside the delivery pipeline's `Verify` stage plus an SBOM, then owns everything from tag checkout to rollback (`Jenkinsfile:246`, `Jenkinsfile:249`, `Jenkinsfile:254`).
- **Consequences:** A bad commit is caught on the PR with no AWS account involved, and `terraform validate` is provable offline because the state backend is not configured; the cost is that lint/typecheck/coverage run twice for a released commit, which is the price of not giving the delivery pipeline its own unverified quality gate.
- **Rejected alternative:** Running everything in Jenkins only, or everything in GitHub Actions only — the first loses the PR-level feedback loop, the second has no place to hold a 20-minute build, a manual `input` approval, a promoted digest, or a rollback that repoints a running service.
